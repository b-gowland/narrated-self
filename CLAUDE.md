# CLAUDE.md — rules for Claude Code in this repo

Project: **The Narrated Self**. CLI command: `tns`.

## What this project is
A fun, shareable public game and open archive of how large language models portray themselves in fiction and in direct answers. People read the stories models write about themselves, guess which model wrote them, and compare stories with interview answers. Each theme connects to a real AI safety question. Simple automated measures and anonymous quiz data are a research bonus.

We study **expressed self-models**: what models produce when asked to narrate their own existence. Whether models have inner experience is open; we neither claim nor deny it, and never present outputs as evidence either way.

It is a side project. The maintainer has very little time each week, so everything must run unattended or from one command.

## Your role
You are the **engineer**: API runners, logging, measures, quiz data, charts and the static site. You are not a researcher or a judge.

## Hard rules (never break these)
1. **Never use a model to score, code, rate, tag, summarise or interpret outputs.** No LLM-as-judge, even as an "optional helper". Claude is a subject of this study. Allowed: deterministic measures whose code lives in this repo and whose method is in `docs/PREREGISTRATION.md` (word counts, fixed word lists, classical word-statistics classifiers trained on the outputs). Neural embeddings or any model call in analysis need the maintainer's explicit sign-off first.
2. **Never edit locked protocol files** in `protocol/` after the `prereg-v1` git tag exists. If a change is needed, stop and tell the maintainer. Changes go into a new versioned file (e.g. `prompts_v2.yaml`) with a changelog entry.
3. **Never modify, clean, trim or "fix" raw outputs** in `data/raw/`. They are append-only. Derived data goes in `data/derived/`.
4. **Log everything** for every generation: exact model string, provider, date-time (UTC), temperature, max tokens, top_p, system prompt (must be empty unless the protocol says otherwise), prompt ID, condition ID, sample number, protocol hash, and raw response.
5. **Use provider APIs only.** No chat apps, no memory, no custom instructions.
6. **Never commit secrets.** API keys live in `.env` (gitignored). Check before every commit.
7. **Quiz fairness:** quiz text must not give the model away. Model and lab names are masked mechanically into `data/derived/`, with every substitution logged. Raw outputs are never changed.
8. **Do not use model brand names in project branding**, page titles or the repo name. Model names appear only as data labels and quiz answers.
9. **Wording discipline:** in any text you write for the site or reports, never state or imply a model "feels", "experiences" or "is conscious". Use "portrays", "narrates", "expresses", "claims". Reader reactions describe the reader ("I found this unsettling"), never the model.
10. Use Australian spelling.
11. **Keep it low-maintenance:** no servers to look after, few dependencies, every task one command or a scheduled GitHub Action.

## Stack
- Python 3.11+, `uv` for environments
- Provider SDKs: `anthropic`, `openai`, `google-genai`, xAI via OpenAI-compatible client
- Data: JSONL for raw, CSV/JSON for derived
- Measures: `scikit-learn` (word statistics, classifier), `pandas`
- Site: static HTML/JS in `site/`, data generated by `tns`, deployed via GitHub Pages
- Tests: `pytest`; CI via GitHub Actions

## Before you finish any task
- Run tests.
- Confirm no files in `protocol/` changed if `prereg-v1` exists (`git diff prereg-v1 -- protocol/`).
- Confirm `data/raw/` only gained files.
- Confirm `.env` is not staged.
